Computability

Last modified: 2026-11-11 00:40:31 (PST)

Some problems have no algorithm at all, however much time is allowed. No Turing machine decides whether a program halts. The proof uses an argument called diagonalization, and the same argument shows that more time lets machines decide more problems. These results build on the models of computation page, which defines Turing machines, their descriptions as strings, and the universal machine.

1 Decidable problems

Definition 1 (Decidable problem) A decision problem \(L\) is decidable if some Turing machine decides it: the machine halts on every input \(x\), with output \(1\) if \(x \in L\) and \(0\) if \(x \notin L\). A problem that no Turing machine decides is undecidable (Arora and Barak 2009, sec. 1.5).

Example 1 (Decidable problems from P and NP) The palindromes are decidable, because the machine of the palindrome example decides them. INDSET is decidable too, even though no polynomial-time algorithm for it is known: it is in NP, so a machine can run its verifier, with certificate length \(q\) as in the definition of NP, on each of the \(2^{q({\mathopen{}\left|x\right|\mathclose{}})}\) possible certificates in turn, and accept if any certificate passes. That search takes exponential time, but it always halts. Decidability asks only whether a machine that always halts exists, not how long it takes.

2 An undecidable problem

Definition 2 (The diagonal problem) The diagonal problem UC is the decision problem whose yes inputs are the strings \(w\) such that the machine \(M_w\) that \(w\) describes, run on its own description \(w\), does not halt with output \(1\):

\[\text{UC} \stackrel{\text{def}}{=}{\mathopen{}\left\{w \in {\mathopen{}\left\{0, 1\right\}\mathclose{}}^* : M_w(w) \ne 1\right\}\mathclose{}},\]

where \(M_w(w) \ne 1\) includes the case that \(M_w\) never halts on \(w\) (Arora and Barak 2009, sec. 1.5).

Example 2 (Machines in and out of the diagonal problem) If \(w\) describes a machine that outputs \(1\) on every input, then \(M_w(w) = 1\), so \(w\) is not in UC. If \(w\) describes a machine that outputs \(0\) on every input, or one that runs forever on every input, then \(w\) is in UC. If \(w\) describes the palindrome machine of the palindrome example, then \(w\) is in UC exactly when \(w\) is not itself a palindrome.

Theorem 1 (The diagonal problem is undecidable) The diagonal problem UC is undecidable (Arora and Barak 2009, sec. 1.5).

Proof. Suppose a Turing machine \(M\) decides UC, and let \(w\) be a description of \(M\), so that \(M_w = M\). Then \(M\) halts on \(w\) with output \(1\) or \(0\).

  • If \(M(w) = 1\), then \(w \in \text{UC}\), because \(M\) decides UC. By Definition 2, \(w \in \text{UC}\) means \(M_w(w) \ne 1\), that is, \(M(w) \ne 1\), a contradiction.
  • If \(M(w) = 0\), then \(w \notin \text{UC}\), because \(M\) decides UC. By Definition 2, \(w \notin \text{UC}\) means \(M_w(w) = 1\), that is, \(M(w) = 1\), a contradiction.

Both cases are impossible, so no Turing machine decides UC.

Remark 1 (The diagonal argument). Picture an infinite table with one row for each binary string \(w\), one column for each binary string \(x\), and the entry in row \(w\) and column \(x\) equal to \(M_w(x)\), or to a mark for “runs forever”. Each row lists everything one machine does. UC is built from the diagonal entries \(M_w(w)\), and it disagrees with row \(w\) in column \(w\) for every \(w\), so no row decides it. Arora and Barak (2009, chap. 3) use the same idea to prove the hierarchy theorems.

3 The halting problem

Definition 3 (The halting problem) The halting problem HALT is the decision problem

\[\text{HALT} \stackrel{\text{def}}{=}{\mathopen{}\left\{\mathopen{}\left\langle w, x\right\rangle\mathclose{} : M_w \text{ halts on input } x\right\}\mathclose{}},\]

where \(\mathopen{}\left\langle w, x\right\rangle\mathclose{}\) is the pair encoding of \(w\) and \(x\), and \(M_w\) is the machine that \(w\) describes (Arora and Barak 2009, sec. 1.5).

Example 3 (Pairs in and out of the halting problem) Suppose \(w\) describes a machine that halts at once if the first symbol of its input is \(0\), and otherwise moves its input head right forever. Then \(\mathopen{}\left\langle w, 0\right\rangle\mathclose{}\) and \(\mathopen{}\left\langle w, 011\right\rangle\mathclose{}\) are in HALT, and \(\mathopen{}\left\langle w, 1\right\rangle\mathclose{}\) is not. Neither is \(\mathopen{}\left\langle w, x\right\rangle\mathclose{}\) for the empty string \(x\), because the first symbol the machine reads after \(\triangleright\) is then a blank, not \(0\).

Theorem 2 (The halting problem is undecidable) The halting problem HALT is undecidable (Turing 1937; Arora and Barak 2009, sec. 1.5).

Proof. Suppose a Turing machine \(H\) decides HALT. Build a machine \(D\) that, on input \(w\), does the following:

  1. Run \(H\) on \(\mathopen{}\left\langle w, w\right\rangle\mathclose{}\).
  2. If \(H\) outputs \(0\), then \(M_w\) does not halt on \(w\), so \(M_w(w) \ne 1\) and \(w \in \text{UC}\): output \(1\).
  3. If \(H\) outputs \(1\), then \(M_w\) halts on \(w\). Run the universal machine \(U\) on \(\mathopen{}\left\langle w, w\right\rangle\mathclose{}\), with \(w\) as the description and as the input, which halts with output \(M_w(w)\). Output \(0\) if \(M_w(w) = 1\), and \(1\) otherwise.

\(H\) halts on every input, and step 3 runs \(U\) only when \(M_w\) halts on \(w\), so \(D\) halts on every input. Its output is \(1\) exactly when \(M_w(w) \ne 1\), so \(D\) decides the diagonal problem UC. This contradicts Theorem 1, so no Turing machine decides HALT.

Remark 2 (Undecidability in practice). Turing machines can simulate programs in ordinary programming languages (the Church-Turing thesis), so Theorem 2 says that no program can check, for every program and input, whether that program finishes. A job scheduler that runs users’ model-fitting code cannot predict which jobs will loop forever, so it stops jobs with a time limit instead. Tools that always finish and check code for infinite loops exist, but on some programs each one must answer “unknown”, miss a loop, or flag a program that does halt. The proof that Kolmogorov complexity cannot be computed is a second example of an uncomputable function, proved by a different argument.

4 The time hierarchy theorem

Definition 4 (Time complexity class) Let \(T\) be a function from the nonnegative integers to the positive real numbers. The class \(\text{DTIME}(T(n))\) is the set of decision problems \(L\) such that some Turing machine decides \(L\) and runs in time \(T'(n)\) for some function \(T'\) with \(T'(n) = {O\mathopen{}\left(T(n)\right)\mathclose{}}\) (big-O notation). Arora and Barak (2009, sec. 1.6) require a running time of at most \(c \, T(n)\) for a constant \(c\) and every \(n\). Because \(T(n) > 0\), the two definitions agree: a larger \(c\) covers the finitely many \(n\) below the threshold of \({O\mathopen{}\left(\cdot\right)\mathclose{}}\).

Example 4 (Palindromes and the class P) The palindrome machine runs in time \(3n + 4\), which is at most \(7n\) for every \(n \ge 1\) and so is \({O\mathopen{}\left(n\right)\mathclose{}}\), so PAL is in \(\text{DTIME}(n)\) (time complexity class). The class P is the union of \(\text{DTIME}(n^c)\) over all constants \(c \ge 1\).

Theorem 3 (More time decides more problems) The time complexity class \(\text{DTIME}(n)\) is a proper subset of \(\text{DTIME}(n^{1.5})\) (Arora and Barak 2009, sec. 3.1).

Proof. Every problem in \(\text{DTIME}(n)\) is in \(\text{DTIME}(n^{1.5})\), because \(n = {O\mathopen{}\left(n^{1.5}\right)\mathclose{}}\). For the other half, let \(U\) be the universal machine, and build a machine \(D\) that, on an input \(x\) of length \(n\), does the following:

  1. Copy the pair encoding \(\mathopen{}\left\langle x, x\right\rangle\mathclose{}\) onto a work tape.
  2. Compute the number \(t = \mathopen{}\left\lfloor n^{1.4}\right\rfloor\mathclose{}\) in binary on another work tape.
  3. Run \(U\) on \(\mathopen{}\left\langle x, x\right\rangle\mathclose{}\), which runs the machine that \(x\) describes on input \(x\), and subtract \(1\) from \(t\) after each step of \(U\). Stop \(U\) when \(t\) reaches \(0\).
  4. If \(U\) halted within those steps with output \(b \in {\mathopen{}\left\{0, 1\right\}\mathclose{}}\), output \(1 - b\). Otherwise output \(0\).

Steps 1 and 2 take \({O\mathopen{}\left(n \log_2 n\right)\mathclose{}}\) steps: \(D\) writes \(\mathopen{}\left\langle x, x\right\rangle\mathclose{}\), counts the symbols of \(x\) in binary, then does arithmetic on numbers of \({O\mathopen{}\left(\log_2 n\right)\mathclose{}}\) digits. Step 3 runs \(U\) for at most \(n^{1.4}\) steps, and each subtraction takes \({O\mathopen{}\left(\log_2 n\right)\mathclose{}}\) steps, so step 3 takes \({O\mathopen{}\left(n^{1.4} \log_2 n\right)\mathclose{}}\) steps, which is \({O\mathopen{}\left(n^{1.5}\right)\mathclose{}}\) because \(\log_2 n = {O\mathopen{}\left(n^{0.1}\right)\mathclose{}}\). So \(D\) halts on every input, and the problem \(L\) that \(D\) decides is in \(\text{DTIME}(n^{1.5})\).

Suppose \(L\) is also in \(\text{DTIME}(n)\). Then some Turing machine \(M\) decides \(L\), and there are a constant \(c \ge 1\) and an integer \(n_0\) such that \(M\) halts within \(c \, n\) steps on every input of length \(n \ge n_0\). Let \(x\) be an input of length \(n \ge n_0\), and let \(w\) be any description of \(M\). By ?@thm-universal-tm, \(U\) halts with output \(M(x)\) within \(C \, c \, n \log_2 (c \, n)\) steps when it runs \(M_w\) on \(x\), where \(C\) depends on \(M\) but not on \(w\) or \(x\). That bound is \({O\mathopen{}\left(n \log_2 n\right)\mathclose{}}\), so there is an \(n_1 \ge n_0\) such that the bound is less than \(\mathopen{}\left\lfloor n^{1.4}\right\rfloor\mathclose{}\) for every \(n \ge n_1\). \(M\) has infinitely many descriptions, so it has a description \(x\) of length at least \(n_1\). On that input, \(U\) finishes within the \(\mathopen{}\left\lfloor n^{1.4}\right\rfloor\mathclose{}\) steps that \(D\) allows, with output \(b = M(x)\), so \(D(x) = 1 - M(x) \ne M(x)\). But \(M\) and \(D\) both decide \(L\), so \(M(x) = D(x)\), a contradiction. So \(L\) is not in \(\text{DTIME}(n)\).

Theorem 4 (The time hierarchy theorem) Let \(f\) and \(g\) be time-constructible functions with \(f(n) \log_2 f(n) = o(g(n))\) (little-o notation). Then the time complexity class \(\text{DTIME}(f(n))\) is a proper subset of \(\text{DTIME}(g(n))\) (Arora and Barak 2009, sec. 3.1).

Remark 3 (Proof and consequences of the time hierarchy theorem). A refinement of the proof of Theorem 3 proves Theorem 4. It uses the same diagonal machine, but with a clock that costs a constant number of steps per simulated step on average, in place of the \({O\mathopen{}\left(\log_2 n\right)\mathclose{}}\) steps per subtraction in the proof of Theorem 3. That proof could afford the extra \(\log_2 n\) factor only because \(n^{1.4}\) and \(n^{1.5}\) differ by a power of \(n\). The \(\log_2 f(n)\) factor in the hypothesis is the overhead of the universal machine in the universal machine theorem. Since \(n^c \log_2 n^c = o(n^{c + 1})\), \(\text{DTIME}(n^c)\) is a proper subset of \(\text{DTIME}(n^{c + 1})\) for every integer \(c \ge 1\), so the class P is not equal to \(\text{DTIME}(n^c)\) for any single constant \(c\).
